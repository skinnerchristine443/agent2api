# agent2api

> 把多个 AI 编程平台的账号额度，统一反代成 **OpenAI / Anthropic 兼容 API** 的自托管网关（个人自用）。

**agent2api** 把 **WorkBuddy / Trae** 的账号登录态，通过一个自托管服务暴露成标准的
OpenAI / Anthropic 接口，供任意兼容客户端（各类 CLI、SDK 与脚本）调用。

> **部署形态：只考虑服务器（无头）部署。** 本网关运行在服务器上，不依赖、也不考虑本机桌面
> 客户端的伴随运行；因此任何需要桌面客户端运行时才能完成的事（例如解封只由客户端原生存储
> 持有的密钥）都在本项目的范围之外。

- **接入平台**：WorkBuddy · Trae 的平台接口
- **下游**：任何 OpenAI / Anthropic 兼容客户端
- **范式（两条腿，缺一不成立）**：① 签到 / 活跃打卡拿额度 → ② 反代成统一出口

---

## 定位与边界

**本项目是个人自用工具，不是对外服务，也不做「中转站」。**
判据一句话：**「这把能力是给我自己用的，还是给『别人』用的？」后者一律不做。**

**明确不做**（带「中转站特征」的能力）：

- **多用户 / 多租户**：账号注册、用户管理、按用户隔离额度。
- **按使用者分发的 API 密钥体系**（多密钥 / 密钥分组 / 按用户分发额度）—— 本项目只有自用的两把**用途分离**密钥（控制台口令 + 调用密钥，见下）。
- **账号分组 / 分组级策略**（面向「运营多个池」的组织能力）。
- **对外暴露额度 / 用量 / 计费端点**（供第三方消费即为分发）。
- **远程配置下发 / 灰度** · **对外公告 / 赞助 / 运营面板** · **账号共享与额度分润**。

**配套的默认实践**：

- 默认只监听 `127.0.0.1`；容器端口默认发布到 `127.0.0.1:3010`。**非环回绑定必须已启用密钥，否则启动直接拒绝。**
- **管理面与调用面分离**：控制台（`/api/*`）用**控制台口令**，且**只接受环回来源**（可用 `AGENT2API_CONSOLE_ALLOWED_CIDRS` 显式放宽）；数据面（`/v1/*`）用**调用密钥**。调用密钥**打不开控制台** —— 因此把密钥交给客户端不再等于交出管理权。
- 账号导入 / 导出只用于**本人在自有机器间迁移**，不得用于分享账号。
- `/health` 免鉴权，仅用于健康检查，不泄露任何业务信息。

## 特性

- **多渠道路由**：WorkBuddy（`cn` / `global` / `intl`）· Trae（`cn`）；同名模型可跨区合并候选集。
- **进程内实现**：渠道运行时不依赖任何外部 CLI / 子进程，单二进制即可运行；进程数不随账号数增长。
- **倍率优选调度**：优先选择消耗倍率最低的账号；未知倍率绝不当作免费。
- **到期额度优先**：即将过期的额度先用（主窗口默认 3 天、次窗口默认 7 天，可在控制台按「天」调整）。
- **会话亲和**：同一会话尽量固定在同一账号，减少上下文漂移。
- **签到 / 活跃打卡**：按渠道配置「主 + 兜底」双时间段，自动领取每日额度。
- **账号日守门**：可按渠道（**设置 › 签到 › 账号默认**）设**保留额度下限**与三级日限额（总 token / 积分 / 单模型 token），本地零点解封、免费模型豁免；全被守门时返回专属 429。
- **内容误报缓解（WorkBuddy，默认开）**：出站指纹净化（键值剥离 / 语义句最小改写 / 反探测数字破形）+ 误报降级门（触发后至次日零点切中性策略）；各带开关。
- **三协议出口**：`openai-completions` · `anthropic-messages` · `openai-responses`（走翻译路径）。
- **内置控制台**：账号管理、额度与倍率、请求日志、设置（前端产物已内嵌进二进制）。
- **管理面与调用面分离**：控制台用**控制台口令**（`/api/*`，且只接受环回来源），客户端用**调用密钥**（`/v1/*`）——调用密钥打不开控制台。两把密钥首启各自独立生成：**终端运行（TTY）在日志打印一次；容器等非终端环境写入数据目录 `initial-keys.txt`（0600）**。历史部署的控制台口令与调用密钥相同，在控制台轮换一次即真正拆分。

## 渠道矩阵

| 渠道 | 区域 | 运行形态 |
|---|---|---|
| **WorkBuddy** | `cn` + `global` + `intl` | 进程内（CN 每日签到；Global 每日活跃打卡；Intl 不声明签到） |
| **Trae** | `cn` | 进程内（出站请求体白名单 + 缓存 token 统计） |

> 渠道的唯一事实来源是 `internal/providers/registry.go` 的 `List()`；本表可能滞后，**以代码为准**。

## 快速开始

### 前置条件

| 工具 | 版本 | 用途 |
|---|---|---|
| Go | ≥ 1.26.0 | 构建 / 运行网关 |
| Node | ≥ 20 | 构建前端（使用 npm） |
| Docker | 任意较新版本 | 容器化部署（本地开发非必需） |

### 方式一：Docker（推荐）

```bash
# 一键部署：首次自动生成 deploy/.env；脚本会取出并打印首启密钥（容器内取自数据目录 initial-keys.txt）
./scripts/start.sh
```

或手动：

```bash
cd deploy
docker compose up -d            # 默认只监听 127.0.0.1:3010
docker compose logs -f agent2api
```

### 方式二：本地源码运行

```bash
# 1. 构建前端并嵌入到 Go（产物写入 internal/webui/static/）
cd frontend && npm ci && npm run sync && cd ..

# 2. 运行（读取环境变量 / .env）
go run ./cmd/server
```

服务默认监听 `127.0.0.1:3010`，首次启动会生成**调用密钥**：终端运行在日志打印一次；非交互（容器 / 重定向）写入数据目录 `initial-keys.txt`（0600）。

> 打开 `http://127.0.0.1:3010` 进入控制台，先在 **Accounts** 页按渠道添加账号，再接入客户端。
> 控制台口令与调用密钥相互独立（首启各自生成）。历史部署两钥相同，在 **设置 › 密钥** 轮换一次即可拆分。

> ⚠️ 单账号并发上限**不是**环境变量 —— 它是**渠道级**设置（控制台 **设置 › 签到 › 账号默认**，按「渠道 × 区域」统一配置 `max_inflight`，默认 4；保存后物化到该渠道所有账号）。

> **构建提示**：前端构建与全量 Go 测试**不要并行**（内存压力大）。

## 配置项

配置通过环境变量读取（本地开发可放在 `.env`，Docker 用 `deploy/.env`）。属于本项目自身的变量使用
`AGENT2API_*` 前缀；完整清单见仓库根 `.env.example` 与 `deploy/.env.example`。

| 变量 | 说明 |
|---|---|
| `HOST` | 监听地址（容器内通常设为 `0.0.0.0`） |
| `PORT` | 监听端口（默认 `3010`） |
| `AGENT2API_DATA_DIR` | 数据目录：SQLite 与账号凭证落盘处。⚠️ **删除会丢失全部账号凭证** |
| `AGENT2API_RUNTIME_DIR` | 运行期临时目录 |
| `AGENT2API_HOME` | 渠道运行时的宿主目录 |
| `AGENT2API_PROXY_URL` | 出站代理（`http` / `https` / `socks5` / `socks5h`）；渠道级默认可覆盖（**设置 › 签到 › 账号默认**） |
| `AGENT2API_MAX_RETRY_ACCOUNTS` | 单次请求最多尝试的账号数 |
| `AGENT2API_CONSOLE_KEY` | 控制台（管理）口令。**与调用密钥相互独立**：首启即生成随机值——TTY 下日志打印一次 / 非 TTY 写入数据目录 `initial-keys.txt`（2026-10-07 起；此前版本由调用密钥播种，既有部署保持原值、在控制台轮换一次即完成拆分） |
| `AGENT2API_CONSOLE_ALLOWED_CIDRS` | 除环回外允许访问控制台的来源网段（留空 = 仅环回）。优先用落在主机上的隧道，而不是放宽这里 |
| `AGENT2API_ENABLE_PPROF` | 开启 pprof 调试端点（默认关闭；开启后仍需控制台口令，且受来源限制） |
| `AGENT2API_CORS_ORIGINS` | 数据面（`/v1/*`）CORS 来源白名单（**留空 = 通配 `*`**；填写后仅白名单来源可跨域调用，浏览器端客户端需列在此） |
| `AGENT2API_UPDATE_*` | 托管更新集成（socket 路径 / agent 地址 / token） |

## 部署

- **形态**：只考虑**服务器（无头）部署**；单二进制（前端已内嵌）+ 一个 SQLite 数据目录，**服务器无需安装 Go / Node**。
- **镜像**：多阶段构建，运行时镜像不含 Node；默认只发布 `127.0.0.1:3010`。
- **数据目录**：须可写并收紧权限（凭证落盘于此）。⚠️ **删除数据卷会丢失全部账号凭证**。
- **首次启动**：自动生成**调用密钥**与控制台口令（各自独立随机）；TTY 下日志打印一次，非 TTY 写入数据目录 `initial-keys.txt`（0600）。历史部署在控制台轮换一次完成拆分。
- **管理面边界条件**：控制台来源闸只认**真实连接地址**（不信任 `X-Forwarded-*`）；前置同机反向代理 / NAT 会令来源塌缩为可信地址、防线只剩口令 —— **优先用主机终结的隧道，不要同机反代**。
- **更新链信任面**：控制台口令可经托管更新链触发容器镜像替换（等价最高运行权限）——按最高敏感级保管；更新状态见控制台「设置 › 更新」页。
- **出网**：需要能访问各接入平台；支持配置出站代理。

> 部署环境要求与回滚详见 [`docs/01-系统方案.md`](docs/01-系统方案.md) §1.7–§1.8。

## API 使用

把任意 OpenAI / Anthropic 兼容客户端的 Base URL 指向：

```
http://<主机>:<端口>/v1
```

鉴权使用启动时生成的**调用密钥**：`Authorization: Bearer <调用密钥>`（获取方式见「快速开始」）。

| 端点 | 协议 |
|---|---|
| `/v1/chat/completions` | OpenAI 兼容 |
| `/v1/messages` | Anthropic 兼容 |
| `/v1/responses` | Responses 协议（走翻译路径） |
| `/v1/models` | 模型目录 |
| `/api/*` | 内置控制台（**控制台口令**；默认仅接受环回来源） |
| `/health` | 健康检查（免鉴权） |

`provider/model` 前缀可指定渠道；不带前缀时是否跨渠道，由**设置 › 运行参数**里的模型池决定。
