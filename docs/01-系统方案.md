## 1. 系统总览

### 1.1 定位与边界

**agent2api** 把多个 AI 编程平台的账号额度，统一反代成 **OpenAI / Anthropic 兼容 API**，供个人自用。

- **上游**：WorkBuddy / Trae 的平台接口
- **范式**：**① 签到或活跃打卡拿额度 → ② 反代成统一出口**（两条腿，缺一不成立）
- **不做**：多用户 / 多租户 · 按使用者分发密钥 / 密钥分组 / 额度分配 · 账号分组 · 对外额度 / 计费端点 · 远程配置下发（完整边界见 `docs/02-功能清单.md` §6）
- **密钥形态**：**权限分离** —— 管理面「控制台口令」（`/api/*`，默认仅环回来源）与数据面「调用密钥」（`/v1/*`）相互独立；调用密钥打不开控制台。这不是「按人分发」，不在上一条禁止之列

**评审前置过滤器（边界判据）**：

**本项目是个人自用工具，不是对外服务，也不做「中转站」。** 判据一句话：**「这把能力是给我自己用的，还是给『别人』用的？」后者一律不做。**

**不做**（带中转站特征，优先级高于任何收益评估）：

- 多用户 / 多租户（注册、用户管理、按用户隔离）
- **按使用者分发**的 API 密钥 / 密钥分组 / 额度分配
- 账号分组与分组级策略
- 对外暴露额度 / 用量 / 计费端点
- 远程配置下发 / 灰度、对外公告 / 赞助 / 运营面板、账号共享与额度分润

> **别和「权限分离」混淆**：控制台口令（管理面）与调用密钥（数据面）是**两把用途不同**的密钥，属**权限分离**，不在上表之列 —— 上表禁止的是**按人分发**。见 `README.md`「定位与边界」。

**允许**：只面向本人的告警 / 备份 / 看板（备份须先加密）。

### 1.2 渠道矩阵（2 条，全部进程内）

| 渠道 | 区域 | 运行形态 |
|---|---|---|
| **WorkBuddy** | `cn` + `global` + `intl` | 进程内：CN 每日签到（计费端点）；Global 每日活跃打卡（两步 web 会话）；Intl 不声明签到（契约未知，未实现） |
| **Trae** | `cn` | 进程内：出站请求体白名单 + 缓存 token 统计 |

```

  → app.New(cfg)                      internal/app/app.go
```

### 1.4 数据模型

| 结构 | 位置 | 要点 |
|---|---|---|
| `Item` | `executor/pool.go` | 池中一个账号快照：`ID` `Provider` `Region` `Runtime` · `Quota` · `Models` / `ProvenModels` · `ModelRates` · `ModelDownUntil` / `ModelBackoff`（**per-model** 冷却） |

| `CheckinWindow` | `accounts/checkin_window.go` | 每渠道的签到双时段：`main_start/main_end` + `fallback_start/fallback_end`（**拒绝跨零点**） |

### 1.5 选号层序（`PickRoute`）

```
① 健康过滤         冷却 / 饱和 / 配额耗尽
② 倍率升序         RateKnown && Rate==0（免费）最优先；未知排最后
③ 到期额度优先     主窗口（默认 3 天）→ 次窗口（默认 7 天），多者优先
④ 区域稳定 tiebreak 仅在「倍率信号不确定」时生效（锁定上次使用的区）
⑤ ID 轮转          前面全打平时才生效 —— 保证无数据时行为不变
```

> 五层之外：**选前**另有每账号**日守门**（保留额度下限 + 三级日限额，超限不参选，本地零点解封，免费模型豁免）；**平级决出时**有 **100ms 突发摊开**（并发不复选同号）与**免费探索搭车**（已知免费层独占时每 30 分钟采样一次未知账号）。细则见 `docs/02-功能清单.md` §2 / §4。

| 配置项 | 默认 | 语义 |
|---|---|---|
| `rate_preference` | 开 | 关闭 → 回落纯轮转 / 旧区域闩锁 |
| `expiry_window_seconds` | 3 天 | **≤0 视为关闭整套到期排序，次窗口一并归零**（总开关语义） |
| `secondary_expiry_window_seconds` | 7 天 | 仅当主窗口打平时才用 |

- 控制台以**「天」**为单位编辑这两个窗口（后端存秒）。
- **默认值只在键缺失时写入** ⇒ 已有部署必须 PATCH 才会变更。
- **跨区混池**：同模型的候选账号在区域间**合并**；但**凭证 / 额度 / 健康度 / 倍率按渠道分存**（否则跨区无法比较）。

### 1.6 安全

| 项 | 做法 |
|---|---|
| 鉴权（数据面） | `/v1/*` 用**调用密钥**；无 / 错密钥一律 **401**；与管理面口令**各自轮换、互不影响** |
| 鉴权（管理面） | `/api/*` 用**控制台口令**，且**只接受环回来源**（`AGENT2API_CONSOLE_ALLOWED_CIDRS` 可放宽）；来源判定在验密钥**之前** —— 调用密钥即便泄露也无法从外部接管控制台 |
| 管理面边界条件 | 来源判定只认**真实连接地址**（刻意不信任 `X-Forwarded-*`）：前置**反向代理 / NAT** 会令来源塌缩（同机代理下全部看似回环），防线只剩口令 —— **建议用主机终结的隧道，而非同机反代** |
| 更新链信任面 | 控制台口令可经托管更新链（宿主 update daemon / socket）触发运行镜像替换 —— 口令等价**最高运行权限**，按最高敏感级保管；更新状态见控制台「设置 › 更新」 |
| 绑定门禁 | 绑定非环回地址时要求**调用密钥非空**，否则拒绝启动（fail-closed：空地址 / `0.0.0.0` / 私网地址 / 主机名都算非环回） |
| 调试端点 | pprof **默认关闭**（未启用时 404）；开启（`AGENT2API_ENABLE_PPROF`）后仍受控制台口令 + 来源双重门禁 |
| 凭证写入 | **原子写**：临时文件 + fsync + rename + **父目录 fsync**，权限 `0600` |
| token 刷新 | **按账号单飞**：并发同一账号只发**一次**刷新（避免上游轮换 refresh token 时写出冲突凭据把账号写坏） |
| 日志 | **脱敏**：只记字段名与数值 / 时间，不记 token、不记完整 body |
| 入站超时 | `ReadHeaderTimeout 10s` · `IdleTimeout 120s`（未设 `ReadTimeout`） |

### 1.7 部署环境要求（通用）

| 项 | 要求 |
|---|---|
| 部署形态 | **只考虑服务器（无头）部署**；不依赖、也不考虑本机桌面客户端的伴随运行 |
| 运行形态 | **单二进制**（前端已内嵌）+ 一个数据目录（SQLite） |
| 操作系统 | Linux（也可运行于 macOS） |
| 内存 | 占用低；**进程数不随账号数增长**（无子进程） |
| 容器 | **正式部署形态**（Docker 为主；裸二进制 = 开发 / 应急）。多阶段构建，**运行时镜像不含 Node**；服务器无需装 Go / Node |
| 端口 | 默认 `3010`；**默认只发布 `127.0.0.1`** |
| 控制台来源 | 默认只接受环回；Docker / 隧道场景用 `AGENT2API_CONSOLE_ALLOWED_CIDRS` 显式放宽（compose 默认已含 Docker 网桥段） |
| 数据目录 | 由环境变量指定；需可写、权限收紧（凭证落盘在此）。⚠️ 注意：删除数据卷会**丢失全部账号凭证** |
| 首次启动 | 自动生成**调用密钥**与**控制台口令**（各自独立随机）；TTY 下启动日志各打印一次，非 TTY（容器等）写入数据目录 `initial-keys.txt`〔0600〕（2026-10-07 起；既有播种部署保持原值可用，日志提示轮换一次完成拆分） |
| 出网 | 需要能访问各上游平台；支持配置出站代理 |

**构建/运行命令**

```bash
export PATH="/path/to/go/bin:$PATH"   # 若 Go 不在 PATH（替换为你的 Go bin 目录）
go build ./...                        # 编译
cd frontend && npm ci && npm run sync # 构建前端并嵌入
go run ./cmd/server                   # 本地运行
```

**⚠️ 资源注意**：前端构建与全量 Go 测试**不要并行**（内存压力大）。

### 1.8 回滚

| 场景 | 操作 |
|---|---|
| 倍率优选出问题 | 关闭 `rate_preference` |
| 到期优先出问题 | `expiry_window_seconds ≤ 0`（连带关闭次窗口） |

| 其他 / 整体 | 切换代码版本（`git log` 选一个已知可用提交） |

### 2.2 Go 后端

- **包名**：全小写单词，禁止 `_` / 驼峰 / `-`；除 `package main` 外必须与所在目录名一致。
- **目录名**：全小写单词，禁止 `_` / 大写 / `-`。
- **源文件名**：小写；多词**必须**用 `_` 分隔。
- **测试文件名**：表达**被测对象或场景**。测试对象就是某个源文件时用 `<源文件>_test.go`；跨文件、契约、场景测试用 `<被测对象或场景>_test.go`。**禁止**用开发阶段代号（`stageN`）、工单号或临时名。
- **导出标识符**：PascalCase，禁止下划线残留；缩写词**必须全大写**（见 §2.5）。
- **非导出标识符**：camelCase，禁止下划线残留。
- **接口名**：**应当**用能力式 `-er` 结尾；聚合 / 角色型接口用角色名词（`Store`、`Provider`、`Agent` 等），属登记例外。
- **类型名**：PascalCase。有主类型的文件，文件名 = 主类型名；**域名模块**（多类型 + 领域 API，如 `registry.go`、`recorder.go`）文件名用领域名。
- **常量**：导出 PascalCase、未导出 camelCase；**禁止** SCREAMING_SNAKE。
- **哨兵错误**：导出 `ErrXxx`、未导出 `errXxx`（包级 `var` + `errors.New`）；**禁止**用 `fmt.Errorf` 冒充哨兵。
- **doc comment**：有注释时首词**必须**等于标识符名；**新增 / 修改**的导出标识符**必须**带注释。存量无注释不强制补齐（ratchet）。
- **json tag**：自有契约一律 snake_case；镜像外部接口的字段名**只能**出现在白名单文件内（§7），**禁止按语义推测上游字段名**。
- **SQL**：手写 SQL 的表名 / 列名用 snake_case。

### 2.3 前端

- **目录**：一级按关注点分（`api/ assets/ components/ hooks/ i18n/ lib/ pages/`），全小写单词。`components/` 二级按**功能域**（与 `pages/` 对齐）；**跨域复用**的视觉原语入 `brand/`；**无语义归属**的通用原语入 `ui/`。**禁止**把组件直接放在 `components/` 根目录。
- **组件文件与组件名**：文件名 PascalCase，命名导出，**文件名必须等于命名导出组件名**。
- **集合模块**：同一文件导出同族多个组件时，文件名用**族名**（如 `skeletons.tsx`、`PageSkeletons` 属此类），**不得**用其中某个组件的名字。
- **纯 hook**：文件名 `use<PascalCase>`；扩展名取决于是否含 JSX（纯逻辑 `.ts`、含 JSX `.tsx`）。
- **Context 模块**：文件名 `<Domain>Context.tsx`，同一文件导出 `<Domain>Provider` 与 `use<Domain>`。Provider 与其消费 hook **不拆分**（共享同一 context 类型，拆开只增加间接层）。**非 hook 的工具函数禁止放在 `hooks/`**。
- **函数与变量**：导出函数 camelCase；`api/` 层的读动作**必须**统一 `fetch*`（**禁止** `get*` / `list*`），写动作用 `update*` / `create*` / `delete*` 等动词前缀；布尔判定**应当** `is*`；局部变量 camelCase。
- **类型**：PascalCase；**必须**用 `type`（**禁止** `interface`）；**禁止** `I` 前缀；组件 Props 统一裸 `Props`。
- **字面量联合类型成员**：单词用小写，多词用 snake_case。
- **模块级不可变常量**：SCREAMING_SNAKE_CASE。
- **CSS**：自定义 class 用 BEM（`block__element` / `block--modifier`），块名 kebab-case；状态用 `[data-*]` 属性选择器；CSS 变量全 kebab `--xxx-yyy`。
- **i18n key**：两类并列，且**两类都必须通过类型校验**（见 §6）：
  - **静态 key**（绝大多数）：扁平 camelCase，**禁止**下划线，**禁止**点分层级；
  - **动态枚举 key**：`<域>_<取值>` —— **仅当**取值来自后端枚举 / 联合类型、且 key 由模板拼接时使用。下划线是「前缀」与「取值」的分隔符，**不可去掉**；取值**必须**经类型化映射收口，禁止裸模板字符串拼接。
- **静态资源**：kebab-case；品牌图标统一 `-mark` 后缀；同类资源**应当**统一格式。

### 2.4 工程与运维

- **文档（交付类）**：`docs/` 下用 `NN-中文名.md`（2 位零填充编号 + `-` + 中文名），编号**必须**连续。
- **根级 Markdown**：全大写基名（`README.md`、`AGENTS.md`）。
- **记录类目录**（`private/`、`.agent-runs/`、`.workbuddy/memory/`）：**不与交付类同规**。建议用中文名、不加数字前缀，并**避免**会失效的语义后缀（如 `-最终版`）。
- **Shell 文件名**：kebab-case，动词 / 用途开头。
- **Shell 变量与函数**：全局常量 UPPER_SNAKE；`local` 变量 lowercase snake_case；函数 snake_case 动词短语。
- **发行资产名**：下划线分隔（项目约定，见 §7），与「文件名 kebab」通则不同。**首次发布后即冻结为对外契约，不再变更**。
- **环境变量**：项目自有变量**必须**统一 `AGENT2API_` 前缀，**子命名空间写在后缀**（`AGENT2API_UPDATE_*`、`AGENT2API_TRAE_*`、`AGENT2API_CONSOLE_*`）；**禁止**另立顶层前缀。通用 / 系统变量（`HOST`、`PORT`、`LOCALAPPDATA`）豁免。
- **配置文件**：沿用工具约定名（如 `vite.config.ts`、`tsconfig*.json`、`Dockerfile`、`docker-compose.yml`）。
- **测试数据与流水线文件**：kebab-case，主名不得含 `_`。

## 6. 配置、环境变量与文案

- **环境变量**：见 §2.4。改名必须**一次改净**（代码 + 部署编排 + 两个 `.env.example` + 安装脚本 + 测试）。

## 7. 自动护栏清单（CI 强制）

| 护栏 | 依赖什么 | 作用 |
|---|---|---|
| gofmt 干净 | CI（`gofmt -l .` 必须为空） | `go vet` / `go build` **都不检查格式**，漂移会静默累积；此护栏是唯一格式关卡 |
| 导入约束断言 | `go test`（`internal/app/architecture_test.go`） | 禁止边清单（按包分组）+ 全局兜底规则（app / api）+ 豁免清单；并保 `internal/api` 目录零生产文件 |
| **能力一致性断言** | `go test`（`internal/app/capability_consistency_test.go`） | 描述符里控制台用来渲染按钮的 `capabilities.{chat,model_catalog,login,browser_login}` 必须与 `Adapter.Supports(...)` 一致 —— **声明有、实现无**的按钮必然失败 |
| 职责边界断言 | 同上 | provider 包不得设置 failover / 计算冷却策略；loopback writer 归属等 |
| 上游 json tag 边界断言 | 同上 | 含大写字母的 `json` tag **只允许**出现在 `internal/providers/` 与 `internal/updater/executor.go`（镜像上游 / 容器引擎 API）；白名单新增须评审 |
| i18n key 类型校验 | `tsc -b`（`npm run build`） | key 必须是字典里真实存在的字面量；动态 key 必须经类型化映射 |
| 前端单元测试 | CI（`npm test`，vitest） | 覆盖 `lib/` 纯函数（format / provider / url）；运行在普通 node 环境 |
| 内嵌资源一致性 | `node frontend/scripts/sync-static.mjs` + `git diff --exit-code -- internal/webui/static` | 前端构建产物必须与内嵌资源一致（改完前端须 `npm run sync`） |
| 验收五件套 | CI（本地等价：`make check`） | `go vet` · `go build` · `go test` · `go vet -tags live` · 前端 `npm run build`（+ `npm test`）· `make check` 另含 `gofmt` 与内嵌资源一致性 |
| 跨平台编译 | CI（`cross-build`：**darwin + linux** × 2 arch，`CGO_ENABLED=0`） | 本仓声称跨平台零 CGO；OS 相关的路径 / 进程差异只有编译器能兜住（Windows 支持面已裁撤） |

> 前端的构建产物与 Go 的编译互不影响：**纯类型改动**（如重命名一个 `type`）在编译期被擦除、产物哈希不变，无需 `npm run sync`；一旦**模块图或运行时代码**变了，就必须同步。

## 8. 变更流程

- **改名 / 移动三步**：先全仓 `git grep` 查出所有引用 → 改 → 复验（旧名残留检查 + 构建 + 测试）。删文件同理，必须回头查谁还在引用。

## 11. 前端方案

> 前端产物内嵌于 Go 二进制（`internal/webui/static`，`npm run sync` 写入）；本节是前端的单一参照。架构总览见 §1；变更史见 `docs/03-更新记录.md`（本地维护、不随仓库上传）。

### 11.1 定位与边界

- **形态**：单用户自用的内嵌控制台（React SPA，嵌在网关二进制里）；**只考虑无头（服务器 / Docker）部署**，不依赖任何桌面客户端。
- **密钥形态**：**权限分离**——管理面「控制台口令」（`/api/*`，默认仅环回来源）与数据面「调用密钥」（`/v1/*`）相互独立（详见 §1.6）。
- **不做**：多用户 / 按人分发密钥 / 账号分组 / 对外运营面板等（判据与清单见 §1.1）。
- **前端原则**：零配置优先、失败必须可见（不静默）、行为等价迁移（重构不改功能语义）。

### 11.2 信息架构（IA）

#### 11.2.1 扁平 7 项（域 → 页面）

| 一级项 | 页面 | 路由 | 页内结构 |
|---|---|---|---|
| **概览** | 工作台 | `/` | 健康条 + 待办收件箱（第一公民）+ 榜单 + 指标卡（sparkline）+ 资源细行 |
| **账号池** | 账号池 | `/accounts` | 渠道页签（workbuddy / trae，各带计数）+ 快捷筛选（需关注 / 在途行动视图）+ 搜索/状态/排序（URL）+ 行式状态卡（行含「签到 / 模型」开关列、「签到状态 + 立即签到」列；操作列常显） |
| **任务** | 任务 | `/tasks` | 成长中心（`capabilities.growth` 静态渠道过滤 + 切换账号骨架刷新 + 幂等领取 + 活动热力图 + 成长日志） |
| **额度** | 额度 | `/quota` | 到期额度优先（左：主/次窗口设置；右：总计 2×2 + 四组明细 + `?account=` 直达定位） |
| **观测** | 请求日志 | `/logs/requests` | 页内三页签（跨路径）：请求日志 / 运行日志（`/logs/runtime`）/ 用量统计（`/usage`） |
| **接入** | 接入 | `/access` | 页内三页签（连接信息 / 调试台 / 模型目录；`?tab=`，默认连接信息） |
| **设置** | 设置 | `/settings` | 页内四页签 `?tab=`：运行参数 / 签到 / 密钥 / 更新 |

- **单一事实源**：`frontend/src/nav/nav.ts` 的 `NAV_DOMAINS`——菜单、页面标题、结构测试均从此读取；**菜单名 = 页面标题 = 同一 i18n key**。导航模型保留「域 → 页」两级类型，但**7 个域全部为单页域**（域行即导航链接）⇒ 侧栏呈现为**扁平 7 项**（批次 8 拆解福利域后达成）。
- **`menu: false` 从属路径**：页内页签的从属路径（`/logs/runtime`、`/usage`）参与页面标题推导与域归属，但不进菜单、不计入单页域判定。
- 登录页 `/login` 独立于域结构；未知路径落 404 页。

#### 11.2.2 路由与跳转

- **URL 深度 ≤2**；页内页签用跨路径（观测）或查询参数（`?tab=`，接入 / 设置）承载，不占菜单层级。
- **详情态**用查询参数：`?request=<id>`（请求日志详情）、`?entry=<n>`（运行日志详情）、`?focus=<accountId>`（收件箱跳转定位 + 高亮）、`?quick=` / `?provider=`（账号池快捷筛选 / 渠道页签）。
- **兼容重定向**（旧路径 → 新路径，清单在 `nav.ts` 的 `NAV_REDIRECTS`）：`/accounts/expiry→/quota`、`/accounts/growth→/tasks`、`/providers→/access?tab=models`、`/auth→/accounts`、`/checkins→/accounts`、`/logs→/logs/requests`、`/system→/settings`、`/system/keys→/settings?tab=keys`、`/system/update→/settings?tab=update`、`/models→/access?tab=models`（旧 `#models` 锚在接入页挂载时改写为页签参数）。**`/welfare` 旧链接**由 `App.tsx` 的 `WelfareLegacyRedirect` 按 `?tab=` 分流：`growth→/tasks`、`expiry→/quota`、`signin`/缺省 `→/accounts`（`?account=` / `?focus=` 随行）。
- **SPA 兜底 = 受控通配（denylist）**（`internal/server/router.go`）：仅 `GET/HEAD` 参与；排除 `/api`、`/v1`、`/health`、`/debug` 前缀；其余（含未知路径）一律返回入口 HTML，由前端路由 / 404 页承接——**前端路由变更无需后端同步**。

#### 11.2.3 菜单体系

- **扁平 7 项**（概览 / 账号池 / 任务 / 额度 / 观测 / 接入 / 设置）：全部 1 击直达；无折叠、无二级菜单（页内分段不占层级）。

- **红线**：不新增一级项、不引入二级菜单。

### 11.3 分层与数据层

#### 11.3.1 目录分层（判据见 §3）

```
api/        只做网络与类型（fetch*/update*/create*/delete*；ApiError / isUnauthorized 单点）
hooks/      通用数据 hooks + UI ticks + Context（Theme / I18n / ApiKey / Overview）+ 域查询 hooks
lib/        无状态工具与纯函数（保持有测试）
components/ 视觉层（ui/ 通用原语 · 按功能域的域组件）
pages/      组装（页面目录化；入口 ≤250 行 / 目录内文件 ≤300 行）
```

**硬规则**：组件不直接 `fetch`；**页面（`pages/**`）对 `@/api` 的值导入 = 0**（类型导入允许），数据获取只经 hooks；`localStorage` 只出现在 `lib/` 与侧栏 UI 偏好；`setInterval` 仅存在于 `hooks/`。

#### 11.3.2 数据 hooks 契约

**`useApiQuery(fetcher, depsKey, opts)`**（`hooks/useApiQuery.ts`）→ `{ data, error, loading, refreshing, refresh }`：

- `fetcher` 以 ref 持有；**`depsKey` 唯一标识一次查询（端点+参数）并加模块前缀**（如 `logs:requests:...`）；
- AbortError 全路径静默（不落 error、不触发 401）；StrictMode 双挂载不产生瞬时错误态；
- 轮询 / refresh 失败**保留旧值**并继续；仅首取 / 换 deps 失败才清空并落 error；
- `pollMs` 支持**动态 null**（条件轮询）；计时用 setTimeout 链（慢响应不叠加）；页面隐藏暂停、恢复立即补取一次（仅轮询实例）；
- **401 模块级去重**（以 apiKey 为代，apiKey 变化即重置）→ `signOut` 单点；
- **在途请求共享**（模块级引用计数）：同一 depsKey 复用同一 promise，`refresh` 与轮询不并发双请求；refs=0 才 abort。

**其余**：`usePagedQuery`（`?page=/size=` 与 URL 同步、**筛选变化经 `filtersKey` 回落第 1 页**、写入一律 `replace`）；`useSheetUrlParam(param)`（**打开 push / 关闭 replace 删参**、保留其余参数、直达首帧只请求一次）；`useNowTick(active)`（共享单例 1s tick）；`useAsyncAction`（pending 去重、卸载安全）。

**域查询 hooks**：各域取数封装为模块（`useLogsQueries` · `useOverviewQueries` · `useModelsCatalog`（`hooks/`）· `useExpiryQueries` · `useGrowthQueries` · `useAccountPool`（`components/accounts/`）），页面只消费——**这是「pages 零 @/api 值导入」的实现方式**。

#### 11.3.3 URL 状态规范

| 参数 | 用于 | 备注 |
|---|---|---|
| `q` | 搜索 | 文本类输入 280ms 防抖后落 URL |
| `page` / `size` | 分页 | 默认值不写 URL |
| `window` | 统计窗口 | **按页各自取值域**（概览 1h/24h/7d；用量 1d/7d/30d，映射 API `days`） |
| `status` / `kind` / `model` / `account` / `stream` / `range` / `from` / `to` / `level` / `provider` / `state` / `id` | 各页筛选 | `kind` ↔ API `error_kind`；`range` = 1h/24h/7d/custom |
| `request` / `entry` | 详情 | Sheet 寻址 |
| `next` | 登录回跳 | `/login?next=<路径+query>` |

**写入语义**：筛选 / 分页 = `replace`（不污染历史）；页签 / 详情 = `push`（可后退关闭）。

#### 11.3.4 轮询策略

| 页面 | 策略 |
|---|---|
| 概览 | 资源 5s · 告警 30s · 其余挂载取数 |
| 请求日志 | **手动刷新（无轮询）** |
| 运行日志 | **3s 条件轮询（仅列表第 1 页；翻页 / 切走即停）**，非交互「实时」指示 |
| 版本更新 | 进行中 2s 条件轮询（完成即停）；1s 计时走 `useNowTick` |
| 其他 | 手动 + 操作后重载 |

全部轮询统一走 `useApiQuery`（隐藏标签页自动暂停）。
