# agent2api · 功能清单

> 本文记录**完整版功能清单**与**功能边界决策**（确定做 / 确定不做见 §6）。
> ⚠️ 上游规则**极易过期**（平台侧一年内多次改版）。凡「上游没有 X」「上游字段叫 Y」这类断言，**必须拿一手证据**（官方文档 / 真实抓包 / 既有解析代码），**不要按语义推测字段名**。

---

## 1. 各渠道功能清单

按**骨架项**自检：登录 · token 预刷新 + 原子写回 · 签到/活跃打卡 · 模型目录 · 倍率数据 ·〔跨渠道能力见 §2〕。

### WorkBuddy（`cn` / `global` / `intl`）

| 功能 | 现状 |
|---|---|
| 登录 | OAuth |
| CN 签到 | ✅ 直连计费签到端点 |
| **Global 每日活跃打卡** | ✅ **两步语义**：① 桌面身分的轻量对话；② 网页端 agent 会话（**ACP over HTTP+SSE**：建会话 → 取沙箱链接与令牌 → SSE 拿连接 ID → JSON-RPC `initialize` / `session/load` / `session/prompt` → 轮询到 `completed`）。**只做②拿不到分** |
| Intl 签到 | 不声明（`intl` 是第三个独立部署：与 `global` 的 token 互不相认，其 token 打 CN 网关也会被拒；签到契约未知 ⇒ 未实现、不猜测） |
| 发放判定 | **按「当天新增的额度包」**判定（身份用资源 ID；周期起点为今天）。**不用聚合余额差值**（会被并发充值污染成假阳性）；判不出来 → **中性，不猜** |
| 兜底可观测 | 判不出来时记录**脱敏**字段名清单（不记 token、不记完整 body），便于首次真机确认字段 |
| 模型目录 | ✅ 资源 ID / 周期起止时间（创建时间是**毫秒时间戳**；空字段不要用） |

### Trae（`cn`）

| 功能 | 现状 |
|---|---|
| 出站**请求体白名单** | ✅ 只放行上游认识的键。上游报「请求体非法」时归类为**请求级错误，不换号**（换号也是同样的请求体） |
| 缓存 token 统计 | ✅ 归一化到 `cache_read_tokens` 与 `prompt_tokens_details.cached_tokens`（**流式与非流式两条路径**都做）；有**端到端护栏测试** |
| 既有能力 | 固定客户端 ID、专用 function 标识、限流码识别 |

## 2. 跨渠道能力

| 能力 | 内容 | 配置 |
|---|---|---|
| **倍率优选** | 优先选消耗倍率最低的账号 | `rate_preference`（默认开） |
| **到期额度优先** | 主窗口（默认 3 天）→ 次窗口（默认 7 天），即将过期的额度先用 | 两个窗口秒数（控制台按**天**编辑） |
| **突发摊开（防复选同号）** | 100ms 窗口内刚被选中的账号不参与新的并发选号（含跨模型突发）；全部候选都在窗口内时**回落最旧**且不粘滞；FillFirst 策略豁免 | 内置（无开关） |
| **跨区混池** | 同名模型在各区域（`cn` / `global` / `intl`）间**合并候选集**；凭证 / 额度 / 健康度 / 倍率**按渠道分存** | 受区域过滤约束 |
| **免费 / 收费实测学习** | 按「账号 + 模型」从响应用量字段学习（免费判定需额度为 0 **且**样本足够）；**跨重启持久化**；已知免费层独占路由时**每 30 分钟搭车采样一次未知账号** | 随倍率优选 |
| **用量观测** | 按 UTC 日 / 模型 / 账号 / **模型 × 账号**聚合 `request_logs`：请求数、Token、**四态 outcome**（正常 / 截断 / 失败 / **客户端取消**）、**缓存命中率**、**吐字速率**（tok/s）；客户端取消**不进账号日账本** | 控制台「Token 用量」页 |
| **签到「主 + 兜底」双班** | 每渠道**两个时间段**；段内**随机**取点（按日期确定性派生，当天稳定）；**兜底仅在当天主班未成功时执行**，且**不得早于主段截止**；跨零点范围**拒绝** | 控制台「福利 › 签到」 |
| **账号日守门** | 每账号：**保留额度下限** + 三级日限额（总 Token / 积分 / 单模型 Token）；本地零点解封；**免费模型豁免**；全被守门时返回专属 429（`daily_guard`）；数据源 = `request_logs`（启动播种 + 完成请求增量） | 账号编辑页（0 = 不启用） |
| **管理 / 调用权限分离** | 「控制台口令」（`/api/*`，默认仅环回来源）与「调用密钥」（`/v1/*`）相互独立；调用密钥打不开控制台 | 控制台内各自轮换 |

> 旧版单点签到时间会**迁移**成「主段 = 该点起、默认时长 60 分钟」的退化段。
> **部分渠道的主段起点有下限**（如每日奖励 10:00 才开领的渠道，主段不得早于 10:00），后端与前端都会拦。

## 3. 协议兼容

| 项 | 支持情况 |
|---|---|
| 出口协议 | `openai-completions` · `anthropic-messages` · **`openai-responses`（翻译路径）** |
| 鉴权 | `Authorization: Bearer <调用密钥>`（数据面）；`/api/*` 用控制台口令（见 §2） |
| `developer` 角色 | ✅ 接受，并按下游需要归一化（丢弃或转为 system） |
| **思考档位** | ✅ 解析多种表达（`reasoning_effort` 字符串或对象、Anthropic `output_config.effort`、`enable_thinking` 等），并**按各渠道模型目录的档位钳制**（**不是原样透传**）—— 客户端要高档而上游只到中档时**自动降档，不会整个请求失败** |
| 工具调用 | ✅ 支持；对**重复 id、并行调用被拆散、孤儿工具结果、跨轮复用同一 id** 做修复 |
| 内置工具（如联网搜索） | 由**调用方自行执行**，请求里通常不出现；若出现于 Responses 路径会被规范化丢弃 |
| 多模态 | **按渠道而异**：有的渠道支持图片，有的只支持文本。**下游声明模型能力时需与渠道实际能力一致**，否则会出现「附件被拒」 |
| 流式 | ✅ SSE；**终止判据用终止事件，不靠长度**。缺终止事件的断流判为**截断失败**，不报成功 |

## 4. 已知上游问题与我们的防护

| 问题 | 表现 | 防护 |
|---|---|---|
| **内容指纹风控** | 上游拦「首条不是 system」、`developer` 角色、以及带第三方工具特征的开篇语 | 丢弃调用方的 system / developer 消息，再按渠道要求补前导 system；出站**逐字指纹脱敏**（键值整段剥离 · 语义句一词最小改写 · 反探测数字串破形；覆盖 content / reasoning / 工具参数）；**误报降级门**（system-prompt / 内容拒绝类误报触发后至次日零点强制丢弃调用方 system；与脱敏**各有开关，均默认开**）；该错误归类为**请求级**（**不冷却账号**） |
| **业务码被文案判据遮蔽** | `400` + 业务码 `14018`（额度耗尽）曾被 `status==400` 判据劫持成请求级错误 ⇒ 不冷却、不换号 | 分类改**精确业务码优先**（`12153` / `11102` / `11128` / `11148` / `6004` / `14018`），状态与文本判据降为兜底；`(status, code)` 组合回归矩阵锁定 |
| **工具调用序列断裂** | 重复 `tool_call_id`、并行调用被拆散、孤儿工具结果、跨轮复用同一 id | 序列修复 + **跨轮复用 id 时重新分配唯一 id 并同步改写配对结果** |
| **流式失败被当成功** | 上游断流且无终止事件 → 返回成功但内容为空 | 以终止事件为准，缺失即判截断 |
| **倍率非法值** | `NaN` / `±Inf` / 负值曾在选号热路径触发崩溃 | 三层拦截（解析层判未知 / 合并时丢弃 / 读取时兜底）+ 排序键**不依赖浮点相等判断** |
| **并发刷新把账号写坏** | 上游轮换 refresh token 时，多次并发刷新会写出互相冲突的凭据 | **按账号单飞**（并发同账号只刷一次）；刷新协程用 `defer` 保证一定发布结果与清理 |
| **会话失效误判（`12153`）** | 另一实例 / 官方客户端轮换 token 会让单次刷新被误判为「会话死」 | 单次拒绝**不落死**：先核对存储凭据是否已被更新（比较-写入竞态抑制），再重试一次；重复拒绝才标 `login_required` |
| **硬配额 / WAF 封锁** | 额度耗尽（`402` / 业务码 `14018`）被当普通报错；边缘对整源返回裸 `403` | 硬配额冷却至**次日 04:00**（上游窗口滚动点）；裸 `403` 判为**来源级封锁**：同源 60s 内 ≥2 个账号命中即**整源快速失败 60s**，不再逐个账号冲击上游 |
| **上游静默改版** | 凭据格式变更、模型目录按客户端标识分桶、计费接口新增 cookie 要求 | 列为**待真机实测**项，未凭猜测改动 |

## 5. 使用与运维要点

- 客户端接入：任何 OpenAI / Anthropic 兼容客户端，把 **Base URL 指向 `http://<主机>:<端口>/v1`**，密钥用启动时生成的**调用密钥**（TTY 日志打印一次 / 非 TTY 见数据目录 `initial-keys.txt`）。
- 控制台接入：用**控制台口令**登录 `/api/*`；默认只能从环回访问（外部先经隧道，或用 `AGENT2API_CONSOLE_ALLOWED_CIDRS` 显式放行）；日志若提示「口令与调用密钥相同」，在 **设置 › 密钥** 轮换一次即完成拆分。
- 加账号：控制台 Accounts 页，按渠道选择 OAuth / PAT / 原生凭证。
- 路由控制：`provider/model` 前缀可指定渠道；不带前缀时是否跨渠道由**设置 › 运行参数**里的模型池决定。
- 签到：控制台「福利 › 签到」按渠道配**主 / 兜底**两个时间段；账号上还需开启该账号的自动签到。

## 6. 决策记录（确定做 / 确定不做）

> 历轮评估的收口结果，**不反复推翻**。判据一句话：「这能力给自己用，还是给『别人』用」——后者一律不做。**本节是持久的做 / 不做登记处**；细粒度排期与编号只在本地工作件（`AGENTS.md`，**不入 git**）跟踪。

### 6.1 确定不做（不再评估）

**定位类**（带「对外服务 / 中转站」特征）：

- 多用户 / 多租户（注册、用户管理、按用户隔离）
- 按使用者分发密钥 / 密钥分组 / 额度分配 · 账号分组与分组级策略 · 账号共享与额度分润
- 对外额度 / 用量 / 计费端点 · 远程配置下发 / 灰度 · 对外公告 / 赞助 / 运营面板
- 一切依赖官方桌面客户端运行的能力（含 `$wbEncrypted` 凭证信封的无头解封）
- 事件链伪造式「成长任务」默认启用（桌面信号类默认跳过）

**能力类**（评估后关闭）：

- 凭据存储层加密 · WebDAV 异地备份 · 导出包加密（本地快照备份保留；异地 = 按需手动拷贝）
- 模型连通性测试端点（已由控制台「API 调试台」覆盖）
- 机器身份多次采样（身份为确定性派生，且派生身份会被上游过滤掉领取行）
- SSRF 出站校验（出站目标固定，暴露面不存在）
- **更新链独立信任根（cosign 签名 / 镜像 digest 固化）**：评估后不做——现校验为同源 `checksums.txt` + release semver 白名单 + 固定镜像仓库（TOFU），信任根即 GitHub 账户本身；签名引入的密钥管理成本大于个人自用场景的收益（审查 P2-5 残留风险，已接受）。再评估条件：出现多用户或第三方镜像分发时。
- **SQLite 只读连接分离**：评估后不做——`SetMaxOpenConns(1)` 是刻意设计（写串行、规避 SQLITE_BUSY 竞争与写放大；读阻塞窗口由 `busy_timeout=5s` 限界）；个人单实例负载下重构面大于收益，管理面读阻塞成为实际观测问题再评估（缺陷驱动）。
- **runtime 数据面密钥同步点移除**（`Manager.ProxyAPIKey` / `ReplaceProxyAPIKey`）：评估后保留（已标注）——当前无读取方（实时密钥在 `auth.Verifier`），但它是「轮换 → runtime 知悉」的显式契约点且有测试锁定；删除属纯清理，待 runtime 重构时一并评估。
- **accounts → providers 只读依赖**（分层方向）：评估后保留——仅两处渠道元数据校验（`ValidateAccountProxy` / `ValidateCheckinSettings`，由 store 账号读写路径调用），providers 注册表为进程内静态描述符；单模块仓库下 interface 注入属单实现者的推测性抽象，收益低于改动面（允许边已在 `internal/app/architecture_test.go` 就地注明）。若未来拆分模块或需替身注入，再行反转。
- Windows 平台支持面（无使用场景；未来真用再评估）
- OpenRouter 等价价换算（纯展示，已有 credits 实际值）
- 运维 CLI · 本地 web 工具代跑 · CodeQL 静态分析
- Traework 兼容 / native 桥接 · `cli` 子进程形态 · MITM / 指纹仿真 / 账号切换器
- Redis 镜像 · 单文件前端降级 · mihomo 出口池 · atrest 进程内存回收 · 桌面凭据导入
- 调用来源 IP / UA 落库（观测子项，已裁）
- 实测成本闭环主干：成本分层 / 权重扩展 / 账本管线（仅保留免费状态学习 + 探索搭车）
- **WorkBuddy 目录多源兜底（personal/models 源）**：已评估不做——Global 的 `/console/enterprises/personal/models` 是 OIDC 页（302 Keycloak / 500 HTML），插件 JSON 目录 `/v2/enterprises/personal/models` 会缺 IDE 可见 id；**IDE 下拉源就是 `/v3/config`**（桌面行为）。单源决策由回归测试锁定（`TestModelsGlobalHTMLErrorDoesNotLeakPage`：不得回退 personal 路径）。第三方目录（models.dev 等）/ 桌面缓存同样**永久不做**。

### 6.2 确定要做（形态已拍板；✅ = 已落地）

- **控制台重构**（2026-10-08 定稿 · 方向 A「精密工程」）：**扁平 6 项** IA（概览 / 账号池 / 福利 / 观测 / 接入 / 设置）· **浅色单主题**（无主题切换）· 页内三页签范式（福利 / 观测 / 设置）· 接入两栏 + 模型目录下置 · 工作台 = 健康条 + 待办收件箱 + 榜单 + sparkline ✅ 已落地（批次 1a–5，commit 见 `docs/03`）
- **成长中心自动化**：分段推进（幂等写 → 连登管家 → 旅行闭环 → 扩档）；桌面信号类默认跳过；不可逆写须人工监督
- **批量导入**：**轻量版**（批量 + 逐项报告；不做预览向导 / 中断恢复）✅ 已落地（2026-10-07）
- **配额阈值告警**：**控制台内形态**（不接第三方推送）✅ 已落地（2026-10-07）
- **思考档位降级可视化**（可选）· **成长中心 heatmap**：**读面**（聚合 API + 数据分节）✅ 已落地（2026-10-07）；**控制台看板 UI** 随成长自动化批次（与 T6/前端一并做，后端不再缺件）。
- **发布管线**：`linux/amd64` 镜像（服务器为 arm 再加 `linux/arm64`）+ `darwin/arm64` 二进制
- **池策略参数化 / 重试纯函数化**：保留（重构类，择期实施）
- **Trae 多通道保底回落**：保留待办（涉及两套新上游协议，真机阶段再分析）
